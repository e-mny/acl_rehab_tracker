Your journal, connected.

A local API for future Telegram input and trusted tools. Download the OpenAPI schema for complete fields and validation rules.

Authentication

Create a token in Settings → Integrations. Send Authorization: Bearer YOUR_TOKEN on each request. Browser sessions use an HttpOnly cookie; browser mutations also require X-Stride-Request: 1. Tokens can manage journal data and photos, but security settings and full ZIP exports require a browser session.

Daily entries

MethodRoutePurpose
GET/api/entriesAll entries, sorted by date
POST/api/entriesCreate one entry; returns ID
PUT/api/entries/{id}Replace an entry; include every field to retain
DELETE/api/entries/{id}Permanently delete an entry
curl http://YOUR-SERVER:8080/api/entries \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"date":"2020-01-15","knee":41.2,"above5":43.7,"above15":53.6,"source":"telegram"}'

Dates use YYYY-MM-DD. There is one entry per date. A duplicate returns 409; read the existing entry and update its ID. At least one metric or a note is required. Optional fields are null when unmeasured. Only send source: "telegram" from a Telegram integration.

Photos, profile and exports

MethodRoutePurpose
GET / PUT/api/profileJournal settings
GET / POST/api/photosList or upload photos
GET/api/photos/{id}/imageAuthenticated JPEG image
PUT / DELETE/api/photos/{id}Update annotations or delete
GET/api/export/csvDownload all entries
GET/api/export/backupZIP archive; browser session required

Photo uploads use multipart fields file, photo_date and optional caption. JPEG, PNG and WebP are accepted, up to 12 MB. Metadata is removed and images are resized. Annotation points use normalized coordinates between 0 and 1.

The optional Telegram and local pose services are configured through Docker Compose profiles. Photo estimates require explicit review before logging. Keep integration tokens in trusted server-side code. See the project README for deployment and backup details.

Partial updates and reviewed measurements

POST /api/entries/preview accepts {"date":"YYYY-MM-DD","values":{"flexion":90}} and returns a merged preview plus a version string without writing data. PATCH /api/entries/by-date/{date} accepts partial entry fields; send the preview version in If-Match to reject conflicting edits. An absent date uses version new.

PATCH, photo uploads and photo application support Idempotency-Key. Retrying the same payload with the same key returns the original response; a different payload with that key returns 409.

POST /api/photos/{id}/analyze accepts {"side":"left"} or right and stores a local landmark proposal. POST /api/photos/{id}/apply accepts date, caption, side, three normalized points, reviewed:true and expected_version. Also send metric (flexion or extension), extension_direction (deficit or hyperextension, required for extension), and optional analysis_id for model provenance. The server computes the signed angle and atomically updates only the selected metric, retaining reviewed evidence with the photo. A proposal alone never changes daily metrics.

GET /api/integrations reports pose availability and Telegram heartbeat status. See the project integration guide for configuration.

New photos are queued automatically when a leg is known. POST /api/photos/{id}/queue queues a stored photo; POST /api/photos/analyze-batch accepts optional photo_ids, side and retry_failed. Jobs survive app restarts and wait while the model service is offline. Analysis never changes daily metrics or saved manual alignments.
